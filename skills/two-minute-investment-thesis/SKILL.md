# 两分钟投资逻辑

## 定位

本 skill 同时承担研究入口和出口：

- **Seed 模式**：先找市场已流通段子，借用别人完成的研究压缩结果快速定位主线。外部段子是“假设包”，不是我方事实或 conviction。
- **Closing 模式**：把 canonical 主笔记、最新模型和验证后的证据压缩成能被记住、复算和转述的估值骨架。

默认闭环：`现成段子 → 拆承重主张 → 按估值影响 × 不确定性验证 → 研究/建模 → 输出更强段子 → 传播并接受市场验证 → 继续迭代`。

## 使用边界

本技能只用于投研整理、假设验证与书面或口头表达，属于研究用途。输出不构成投资建议，也不构成购买、出售、持有或下单的授权。资料、工具和模型调用沿用原任务授权；本技能不扩展付费、通信、经纪或实盘交易权限。

## 先定听众，再定长度

默认假设听众**不了解这家公司，也不了解新业务的单位经济性**。先让他听懂生意如何从物理量变成利润，再追求短。

- 成熟、稳定且听众熟悉的公司，可以用 200–350 个中文字符直接讲分部利润/收入与估值。
- 陌生公司、新业务或单位经济复杂的制造业，通常用 350–550 个中文字符；如果量价利桥仍不完整，可以更长。
- “两分钟”是口头理解和复述目标，不是机械字数上限。压缩不能删掉承重因果链。

交付前先判断：听众是否能回答“卖什么、按什么单位出货、每单位多少钱、怎么变成利润、利润怎么变成市值”。不能就继续补，不得因为已到字数上限而停。

## 模式判断

1. 尚未深入研究，或用户说“先看看市场怎么讲”“找找逻辑”时，用 **Seed 模式**。
2. 已有 journal、canonical 主笔记/模型，或用户要“小段子、两分钟逻辑、给团队讲的版本”时，用 **Closing 模式**。
3. 情况不明时先查本地 journal、主笔记和模型；材料不成熟就产 seed，成熟就 closing。不得把 seed 冒充验证结论。

## Seed 模式

1. 若已安装且可访问，可选用同伴技能 `jeromell-evidence-channels`，按可用性搜索本地材料、你订阅的研究平台、知识星球、卖方/专家交流、微信/公众号、X 等已流通逻辑。未安装或无法访问时，不要声称已加载该同伴技能，直接使用用户提供的材料，按本技能的 Seed 流程处理。不可访问的平台只能读取用户材料或生成精准检索任务，不得假装搜过。
2. 保留来源渠道、作者/机构、发布日期、抓取日期、原文路径和证据层级。0 命中也要记录。
3. 形成 **外部段子种子 v0**：讲清业务角色、最短量价利估值桥、催化和 kill；长度按听众熟悉度调整。
4. 拆成承重主张台账。每条记录：影响公式哪一项、来源层级、不确定性、状态和下一验证动作。状态只用 `未验证 / 保留 / 修正 / 证伪 / 新增`。
5. 按 `对目标市值的影响 × 不确定性` 排验证队列。若已安装且可访问，可选用同伴技能 `research-dialogue` 继续验证；未安装或无法访问时，不要声称已加载该同伴技能，按本技能流程用用户材料继续验证。

Seed 交付必须写：**“这是外部段子种子，不代表我方已验证观点。”**

## Closing 模式

1. 读取 canonical 主笔记、最新 canonical 模型和估值基准日。数字必须与模型一致；无模型只能标“草算”。
2. 读取 seed v0 和主张台账，标记保留、修正、证伪和新增。历史项目无 seed 时注明“无可追溯 seed”。
3. 选择**最短完备驱动链**，而不是任意挑最少数字。通常需要 6–12 个圆整数，足以复原收入、利润和估值。**多业务公司必须分业务写完再汇总**：每一块至少能看出量、价、收入、毛利（或等价利润贡献），再加总成集团收入/归母；禁止只报一个集团利润却让听众猜各块怎么加出来。
4. 把“一个主公式”写成连续经营桥，而不是只写最后一步：
   - 制造/设备：`出货量 × ASP = 增量业务收入；增量收入 + 基本盘 = 总收入；总收入 × 净利率 = 归母；归母 × PE = 市值`。
   - 毛利变化承重时：补 `分部收入 × 分部毛利率 → 综合毛利 − 期间费用 → 税前利润 → 税后归母`。
   - 平台/零售：`交易规模 × 变现率 = 收入；收入 × 利润率 = 利润；利润 × PE = 价值`。
   - 合同型基础设施/地产：`投运容量 × 单位租金 × NOI margin = NOI；NOI ÷ cap rate = 资产 EV；资产 EV + 未签期权折现值 − 净债务 − 剩余 Capex = 股权价值`。必须解释 NOI 是扣除项目运营成本后的经营利润，不是归母净利；未签容量不得与已签、已起租容量混算。
   - 多业务公司：按业务拆开上述桥（最多 2–3 个价值池写细），再相加为集团或 SOTP；**未来年（至少次年，需要时到锚年）用同一套分业务拆法**，不要第一年很细、后面只丢利润总数。
5. 解释业务角色和口径：公司究竟卖整机、部件、服务还是项目；若 ASP 是整套方案口径，要明确它不是单个零部件价格。
6. 写清当前市值及其基准日、目标市值和现价隐含了哪一档。未来终值未折现时明确目标年和口径。
7. 收尾写最关键的验证变量与 kill。另在 journal 记录 `v0 → vN` 的保留、修正、证伪和新增。
8. 写入公司主文档时，放在前部 `## 两分钟投资逻辑` 下；详细证据、三情景和跟踪表留在后文。

与点评类写法对齐：财报/跟踪点评里的预测段同样遵守「分业务量价利 → 汇总 → 未来年」。若已安装且可访问，可参阅同伴技能 `company-commentary`「分部量价利桥」与 `earnings-commentary` 支柱 3；未安装或无法访问时，不要声称已加载这些同伴技能，以本节的分业务量价利桥为准，用用户材料继续。

## 默认段落顺序

自然写成连续段落，不把标签原样堆进正文：

1. 公司原来靠什么挣钱，新弹性是什么；它在产业链里做什么、不做什么。
2. 订单/产能/用户数如何落成核心“量”，ASP/变现率是什么口径。
3. `量 × 价 = 核心收入`，再加基本盘得到总收入。
4. 毛利率、费用率或净利率如何把收入落到归母利润。
5. `利润 × 估值倍数 = 目标市值`，对比当前市值说明市场已交易到哪一步。
6. 乐观和下沿各由哪一个经营变量改变；最后给验证点与 kill。

## 数字和表达纪律

- 用圆整数和单一时间锚，但必须保留完整经营桥。数字少不是目的，能复算才是目的。
- 区分公司披露、模型假设和渠道推断；短段可省完整脚注，不得改变证据层级。
- 不得把分部毛利率、综合毛利率和净利率混用；从收入跳到归母时必须说明利润率口径。
- 使用 NOI/FFO/AFFO 等资产口径时，必须用大白话定义它扣了什么、尚未扣什么，并把 cap rate 资本化、净债和剩余 Capex 到股权价值的桥写全。
- 不得把零部件 ASP、整机 ASP 和整套项目 ASP 混成一个价格。
- 当前市值、目标年、目标倍数和未折现口径都要明确。
- 默认突出中性或偏乐观主路径，但保留一条可量化下沿。
- 不写“行业空间巨大、公司充分受益、估值合理”等无数字套话。
- 不为追求短而删掉听众理解业务所需的定义；也不把历史流水和无关财务指标塞进段子。

## 两种标杆形状

- **陌生制造业**：先讲公司采购机头后交付整套电站；`2GW × 88亿元/GW = 176亿核心收入`，加 193 亿基本盘得到 369 亿总收入；32%毛利率、9%费用率和税率落成 70 亿归母；`70亿 × 24倍 = 1,680亿市值`。听众能沿量、价、利完整复算。
- **合同型数据中心/地产**：先讲公司交付土地、电力和机电、客户自带 GPU；`700MW × 单位年租金 × NOI margin = 7.9亿美元 NOI`，再 `NOI ÷ 5% cap rate = 158亿美元资产 EV`，加未签管线折现值、扣净债和剩余 Capex，得到股权价值与每股目标。不能只报“700MW合同很多”或直接用 NOI 当净利润乘 PE。
- **熟悉的成熟平台**：阿里可以压成零售 `2,000亿利润 × 12倍 = 2.4万亿`、云 `2,000亿收入 × 5倍 = 1万亿`。但若听众不熟悉阿里，必须再补零售的 `GMV × take rate → 收入 → 利润率`，以及云收入为何能到 2,000 亿；不能把上游假设藏在结论数字里。

## 交付前自检

- 当前是“外部段子种子 v0”还是“我方验证版 vN”，是否写清？
- 一个不了解公司的人能否说清公司卖什么、不卖什么？
- 能否沿“量 → 价 → 收入 → 毛利/费用/净利 → 估值”逐步复算，不发生跳步？**多业务时：每一块是否都能单独复算，再加总？未来年是否同一拆法？**
- ASP、利润率和估值倍数各是什么口径、什么年份？PE 只许前瞻（NTM / 当年E / 明年E / 目标年E），禁止 TTM。交付前自检一遍：全文 PE 是否都带年份口径、有无 TTM 混入。
- 当前市值究竟隐含中性、乐观还是下沿？
- Closing 是否交代 v0 到 vN 的变化，且最终版更可验证？
- 删除一句后若会让经营桥断裂，就必须保留；只有不影响因果复原的句子才删除。**不得为压字数删掉某块业务的量或价。**
